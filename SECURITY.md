# Fieldwork personal-first security

Module 2 changes are canonical source only. They have not been installed or migrated into the personal runtime. No company messages, mailbox tests, consent, revocation or credential rotation were performed on the real account during this module.

## Operator authorization

One private operator owns the whole installation. Every existing private API requires either a server-validated session or a private CLI bearer key. There is no default bearer credential; configuring operator/OAuth security also requires a strong API key in local development. A browser never inherits the backend bearer secret from Next.js. The local hostname/no-auth and Basic gates were removed. Operator identity is explicitly `personal`; sessions and integrations reject any other operator at the database boundary. This is not tenant isolation and must not be publicly shared.

The operator password is a unique Fieldwork password, never a Gmail password. A salted scrypt hash stays in external configuration. Browser session tokens are random; only SHA-256 digests are stored, with a 12-hour default expiry, revocation and password-hash version binding. Logout revokes the session; changing the password hash and restarting the API invalidates all existing sessions. Cookies are host-only, HttpOnly, SameSite=Lax and Secure in production. Lax is required for Google's top-level OAuth callback. Exact configured Origin checks and JSON-only mutation bodies prevent browser CSRF; no credentialed wildcard CORS is enabled. CLI bearer authorization is explicit and origin-checked if used by a browser.

Next proxy routing checks a configured host and redirects missing-session browsers to sign-in. These are navigation conveniences; FastAPI checks every private request. Forged and expired cookies cannot access private data. `/health` reveals only database availability. Interactive OpenAPI endpoints are disabled. Error responses omit submitted values and provider exception bodies.

## Gmail lifecycle and secret storage

Connect is an authenticated operator-session POST. The server creates a 10-minute, single-use, session-bound state record with an encrypted PKCE verifier. Callback verifies state/session/expiry and consumes it before token exchange. Redirect URI must exactly match APP_ORIGIN and `/api/integrations/gmail/callback`. Token exchange and identity requests use fixed Google endpoints, HTTPS and no redirects. Gmail profile identity must match the verified student profile, configured sender if set, and the previously connected Gmail address. No account transfer occurs silently.

Default scopes are gmail.send and gmail.readonly. Gmail draft saving requires explicit `GMAIL_DRAFTS_ENABLED=true` and reconnect to grant gmail.compose as well. This broader scope is not requested by default. No label changes, full mailbox scope, password collection, automatic inbound replies or new Outlook production capability exists.

Refresh/access tokens and PKCE verifiers are encrypted using Fernet/MultiFernet. The CREDENTIAL_KEYS keyring lives in external private configuration, never the database, ledger or browser. Client secrets, provider API keys, database credentials and CLI keys remain externally configured. Private `.env` files must be regular owner-only files; production configuration rejects weak/default bearer keys, absent password/encryption setup, plaintext legacy refresh tokens, non-HTTPS origin and wildcard/test hosts. Settings repr and validation errors hide secrets. Production storage needs private network controls and encrypted disks/backups; application encryption covers OAuth secrets, not every profile/database field.

Access refreshes before expiry and verifies provider identity on each connection. Revoked refresh tokens, unreadable ciphertext and account mismatch block access. Decryption failure fences the connection but preserves ciphertext for recovery; explicit disconnect still erases it. Profile email changes invalidate stored authorization. Disconnect erases local tokens, advances the generation fence, pauses recurring/scoped outreach, invalidates outstanding OAuth grants and records an integration transition. Upstream revocation is attempted by default after local invalidation; failure is reported without restoring local access. Receipts and provider IDs survive disconnect. Reconnecting does not resume a campaign. An in-flight reservation may finish before disconnect/pause can take effect; future reservation and transport checks re-read authorization.

## Consequential actions

Company sends still converge on policy.py and delivery.py. Current policy, identity/generation, fingerprints, suppressions, replies, quotas and uncertainty are rechecked at reservation. Jobs do not authorize delivery. Gmail transport permits only enumerated reads, guarded messages/send and guarded draft create/update. Raw draft-send, batch modification and arbitrary Gmail operations are rejected. Provider drafts and own-account tests retain their separate labeled ledger policies; draft saving cannot use a sending endpoint. Unknown/running communication remains a global hold and never automatically retries.

## Ingress, external URLs and logs

FastAPI validates trusted hosts, exact origins, JSON content type, request-target length and a 100 KB default body limit while reading chunks, before parsing. Encoded request bodies are rejected. Next also bounds its request stream before buffering; configure proxy/edge bounds for production transport too. Sensitive rate limits are database serialized: login 5/5min; OAuth 12/5min; sends 10/min; policy/privacy/campaign changes 10/min; other mutations 30/min; reads 240/min. Limits count attempted requests and expire after one hour; no Redis is required. They are keyed by the actual network peer, not spoofable forwarded headers. Through the personal frontend proxy, the single operator shares its backend peer bucket intentionally.

Responses use no-store, nosniff, frame denial and no-referrer; production API adds HSTS. HTTP client, model SDK, SQL parameter and access logging are disabled and structured redaction strips configured secrets, credential fields and Authorization/Cookie content. Do not turn access logging back on for OAuth URLs; configure any reverse proxy likewise. Domain errors are bounded/redacted; arbitrary provider failures store error categories only. No request body, full resume or message body belongs in an operational log.

Research goes through fixed provider endpoints that cannot redirect locally. Company targets must be public HTTPS without credentials/nonstandard ports; all resolved addresses must be public before submitting to Firecrawl. Returned redirect source URLs are revalidated before ingesting evidence. This prevents local backend SSRF; Firecrawl performs remote crawling and owns its internal redirect/network isolation. Fieldwork has no arbitrary local website-fetch endpoint. Resume support is bounded text in JSON, with no binary PDF/DOCX upload/parser or filesystem path derived from a filename; uploads are unsupported.

## Verification and limits

See docs/module2 logs. Fake-provider tests cover OAuth state, PKCE, identity, refresh, revocation, ciphertext failure, disconnect races, secrets, jobs and transport bypass. Browser smoke exercises real disposable Next/FastAPI login/logout and API guards. Real disposable PostgreSQL validates schema/migrations/constraints, competing lock claims, quotas, pause ordering and backup/restore. Local test binaries are PostgreSQL 16.2 from a temporary pgserver wheel, not a production installation; production/CI still targets a maintained patched PostgreSQL 17 image. These are concurrency semantics tests, not certification of that old test server for deployment.

Dependency pins were narrowly patched to Next 16.3.8 and cryptography 50.0.2. npm and pip-audit report no known vulnerabilities for the checked pins. PostgreSQL 17/container builds, TLS termination, live Google app-registration/consent and future SaaS authorization remain later deployment gates. No claim is made that mocked OAuth verifies the real account or Google verification approval.

Primary implementation references: [Google web-server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [Google OAuth storage/revocation practices](https://developers.google.com/identity/protocols/oauth2/resources/best-practices), [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes), [cryptography changelog](https://cryptography.io/en/latest/changelog/), and [Next.js security releases](https://nextjs.org/blog). Dependency scan results describe the local pinned graph and are not a guarantee against undisclosed vulnerabilities.

## Module 4 untrusted intelligence

Models receive no tools, secrets, recipients or authority. External text is sanitized plain text and stays in an untrusted JSON data section. Extraction persists exact matching source quotations only; suspicious instruction/key/recipient/policy strings are quarantined. New generation accepts a strict fact/task plan, not arbitrary claims or model commands. Exact source/student ownership, dates, hashes and contact identity remain application checks; the reviewer score is not proof. Current generated evidence is rechecked at approval and in the existing delivery policy. No detector call, send shortcut, OAuth scope change or tenant claim is introduced.

Provider requests need a single-use reservation from existing Usage. Request, token, model, company/day, personal generation/day and wall-clock bounds apply before real work. No automatic model/network retries; explicit Job retries back off and cap attempts. Research page URLs/redirect sources retain the Module2 DNS/public HTTPS guards and fixed endpoint restrictions. Candidate import rejects private/credential URLs before queue persistence. Rendering uses escaped text and safe external links. Generations are private content records; operational logs do not contain bodies/prompts/resumes/tokens. New content participates in privacy export/erasure. Verification remains fake-provider/disposable-database evidence, not live provider health.

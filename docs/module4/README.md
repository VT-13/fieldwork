# Module 4 — bounded prospect intelligence

Canonical source only. No deployment, real provider validation, mail, real OAuth change or campaign resume is authorized or performed. The personal installed runtime still uses its older schema/source. Do not install these changes casually; follow MIGRATION_PLAN.md and the next authorized release phase.

## Implemented workflow

Discovery → candidate buffer → inspect reported field observations → explicitly accept → canonical Company → sourced Contact → bounded research → current Evidence bundle + deterministic rank → structured AI selection → reference validation → exact attributed claims + supervised proposal → independent quality review → saved draft → operator review/approval. Approval alone never authorizes delivery.

The candidate buffer deduplicates canonical HTTPS domains and preserves alternate names, provider IDs, source dates and search contexts. Similar names at different domains remain distinct. A provider ID associated with conflicting domains becomes ambiguous; operator acceptance chooses a particular domain rather than silently merging them. Acceptance is idempotent and creates no messages. Manual known-company imports are free of provider calls but use the existing durable worker/job path. Candidate context is reported lead information, not verified company evidence. First-class company evidence is collected after acceptance; this phase does not create a second research entity model for unaccepted candidates.

Implemented adapters: Google Places text search, Tavily basic search, Apollo organization search, Firecrawl single-page scrape, Hunter domain search/verifier, OpenAI structured Responses output. They require actual configuration and explicit policy permission for paid calls. Configured is not healthy. LinkedIn/Crunchbase/Wellfound scraping, Gemini, ChatGPT-subscription generation, general website crawling and external AI detector automation are not implemented or advertised.

## Facts, ownership and freshness

Evidence is an exact short source quotation, category, company ID, URL, collection date, source class, qualitative confidence, content hash and verification date. Official company pages supply usable claims. Unrelated redirected third-party pages remain unknown and cannot enter new generation, as do unknown/legacy evidence. A quotation proves what the source said, not that the company's statement is independently true. Extraction does not write unsupported paraphrases or fabricated summary fields. Internship/student/founder categories also require explicit supporting words. Missing descriptions, contacts, role suitability, founder and company size remain unknown. Size buckets require an explicit supported range or bounded employee/team count in the source quotation; customer counts never become employee counts.

Currentness: careers/internship/student 14 days, news/growth/founder 30 days, product/service/description/technology/size 90 days. Cached pages/contacts/search results retain their original retrieval times. A cache hit does not become a fresh source check. Contact roles/emails become stale after 30 days; provider mailbox-validation state is stale after 7 days. Conflicting identity fields are held and preserved. Provider-confirmed means provider-reported, not guaranteed deliverability. DNS validity does not become mailbox verification.

Contact observations preserve name/title/email/profile URL/location where present, provider identity, source URL and dates. Person reconciliation uses email, stable provider ID or exact profile URL, never common names. Different emails linked to one stable identity become a conflict rather than silently replacing the recipient. Executives are held unless small-company context supports their appropriateness; engineers/team leads/recruiting contacts are generally preferred. Conflicts are not automatically resolved; the operator must investigate or select another current sourced contact.

StudentFact records are derived only from the operator-verified structured projects, awards and skills. IDs bind to profile ID + entire current profile hash + field + text. This is an operator attestation, not an independent credential verification service. Raw resumes/background anecdotes/writing samples do not become model evidence. Profile edits invalidate existing approvals.

## Personalization boundary

The model returns an allowed evidence/student-fact selection, task ID and voice. It cannot return arbitrary factual email prose, recipients, executable actions or policy changes. The renderer attributes company quotations exactly, uses the verified identity and selected student facts, and offers a small supervised project matched to selected company/student evidence. A small catalog covers website prototypes, robotics sample-log tools and reporting prototypes. This deliberately limits creative variety in exchange for deterministic factual grounding. There is no promise of higher replies or detector evasion.

Validation rejects unknown/wrong-company/wrong-profile references, duplicate references, unsupported tasks, irrelevant selected experience, free-form/malformed output and unsupported model claims before independent review. The separate reviewer must pass all quality checks with personalization >80. A failed attempt gets at most one bounded revision. Every result retains a distinct Generation ID, immutable prompt identity (selection/review instructions, catalog and renderer digest), provider/model/settings/input hash, references, timestamp, exact subject/body and review. Only a passed result can become a draft; AUTO_APPROVE cannot bypass review. Edits clear review. Attempted/sent/uncertain messages cannot be replaced. A profile, contact or message change during generation holds the result in history rather than overwriting it.

New generated messages recheck their source hashes/freshness, student facts and contact identity at approval and through the existing send-policy boundary. Historical messages keep their existing guarded policy. Follow-up generation retains the original subject and demands a known distinct prior proposal; historical messages without that identity are held for manual research. This does not change due dates, authorization or scheduling; Module 5 owns that integration.

## Limits and usage

Defaults: 30 candidates/job (API import at most 50, processing at most configured limit); 5 contacts; 5 priority pages; 60-second search deadline; 120-second company research deadline; 16 provider requests/job; 7 LLM calls/company/day and job; 12,000 UTF-8 input bytes; 1,800 output tokens; 24,000 conservatively reserved job tokens; 60,000 daily tokens; 2 writing attempts; 2 explicit job retries with exponential backoff. Limits are ceilings, not targets; shared budgets can stop earlier. No automatic rate-limit retry or backfill loop.

Existing Usage rows keep daily/company reservations ($5/$0.75 default) and a personal campaign daily generation cap ($3), measured tokens when returned, conservative token reservations, model, hashes, network units, cache hits and request duration where available. These are spend reservations, not provider invoices. The existing Operation/ActionAttempt owns job identity and success/failure/replay; no second cost ledger exists. Cache hits cost no reserved dollars. A provider request requires a single-use cost reservation. Retry and model/network budgets fail closed. Paid calls remain blocked by MANUAL_MODE or explicit paid_services_authorized=false, including direct configured adapter calls. Page loads perform no paid research/generation.

Discovery cache keys omit presentation context to avoid rescanning the same area for another label. Research stops after company identity/description/contact and two current observations. Useful evidence commits page by page and survives optional-page failures, deadline, stop and provider outages. A missing contact never gets an invented mailbox. Progress shows saved states, counts and sanitized failure categories, not percentages.
